# Домовые камеры

Локальная HTML-страница для регистратора VestaCloud: живое видео, список каналов, поиск и полноэкранный просмотр. Учётные данные читаются сервером из `.env` и не передаются браузеру.

На этом Mac зависимости уже подготовлены. Запуск из каталога проекта:

```sh
sh start.sh
```

Открыть <http://127.0.0.1:8080>. Остановка — Ctrl+C в терминале. Для другого порта: `VIEWER_PORT=8081 sh start.sh`.

При переносе на другой Mac сначала выполнить `sh setup.sh`. Нужны macOS, системный Python 3, `uv`, а на Apple Silicon — Rosetta 2. Настольное приложение Vesta запускать и устанавливать не требуется: используется только транспортная библиотека из официального архива. Библиотека и FFmpeg хранятся локально в исключённом из git каталоге `.runtime/`.

В `.env` используются `SERIAL_NUM`, `USERNAME`, `PASSWORD`. Четвёртый параметр из исходного файла не понадобился для успешного подключения по серийному номеру. Файл исключён из git; его значения не записываются в исходники и журналы.

Сервер обнаруживает публичный сервер XMEye/Xiongmai, открывает P2P-соединение, выполняет DVRIP-вход, запрашивает названия всех каналов и принимает дополнительный видеопоток выбранной камеры. FFmpeg преобразует H.264/H.265 в MJPEG для браузера. Видеозаписи и снимки сервер не сохраняет. Транспорт работает в отдельном процессе; при обрыве выполняется повторное подключение. Страница доступна только на этом компьютере.

Сейчас одновременно показывается **один выбранный канал**, общий для открытых вкладок. Переключение сохраняет инициализированный P2P-клиент, закрывает прежнее соединение и открывает новое соединение с регистратором. Кеш закрытых соединений SDK отключён. Повторный `Claim` на том же соединении проверенная прошивка отклоняет. Видеостена из нескольких камер не реализована. Команда `CONNECT_ALL` сама не включает все камеры. Пустые каналы могут не отдавать видео. Просмотр без звука, до 8 кадров/с; это локальное преобразование, настройки камер не меняются.

Декодирование настроено на малую задержку, с частотой исходного потока из заголовка камеры. Запись в FFmpeg выполняется через ограниченную очередь, чтобы зависший декодер не блокировал проверку состояния. Краткому всплеску данных даётся до 0,5 секунды на разгрузку очереди. Проверяются именно готовые изображения, а не только входящие медиапакеты. При отсутствии готовых кадров, устойчивом переполнении очереди или пропаже heartbeat дочернего процесса сервер переподключается. Старый декодер завершается сразу: для этого потока нет записи, которую нужно дописывать.

При переключении сервер ждёт подтверждения готовности P2P-соединения. Если вход в регистратор не ответил за 3 секунды, выполняется одна повторная попытка на новом соединении; запоздалые ответы прежней DVRIP-сессии отбрасываются. При повторной ошибке остаётся полное восстановление worker-процесса. Причина отсутствия ответа удалённого регистратора на отдельных попытках не установлена.

Каждое переключение и полный перезапуск получают новый номер `generation`, который проходит от команды до готового кадра и `/video?generation=...`. Старый видеозапрос завершается при смене номера. Страница удаляет прежний элемент изображения и снимает заглушку только после загрузки изображения нового запроса. Запоздалые ответы статуса и кадры предыдущих переключений, в том числе при возврате к той же камере, не принимаются.

Диагностика: `/api/status` содержит `diagnostics.timings_ms` — время от начала текущего подключения/переключения до отдельных этапов. `transport_reused=true` означает повторное использование подготовленного P2P-клиента, но не прежней DVRIP-сессии. В `.runtime/viewer.log` сохраняются этапы, счётчики и причины восстановления; журнал ограничен по размеру. Учётные данные, идентификатор устройства, сырые ответы SDK и видеокадры в него не записываются.

Проверки протокола: `python3 -m unittest -v test_protocol.py`.

Старая библиотека производителя предназначена для x86_64/macOS; переносимость на Linux/Windows не проверялась. MJPEG требует больше трафика между локальным сервером и браузером, чем исходный H.265.
