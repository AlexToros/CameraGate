# PostgreSQL

`schema.sql` — исходная идемпотентная схема: пользователи, камеры, группы, приглашения, сессии, сетки и зашифрованные параметры подключения. Её применяет `backend/store.py` при инициализации.

Схема уже развёрнута на VPS. Структура таблиц в рамках реорганизации не меняется. Будущие изменения нужно оформлять версионными миграциями, а не рассчитывать на повторное выполнение CREATE TABLE IF NOT EXISTS.

## Локальная БД

Из корня:

```sh
sh database/scripts/start-local.sh
```

Также запускается автоматически через `scripts/dev/start.sh`, если не задан внешний `DATABASE_URL`. Кластер PostgreSQL 17 — `.runtime/postgres`, сокет — `.runtime/pgsocket`, порт 55432; TCP отключён. Системная служба не создаётся. Путь к утилитам задаётся через `PG_BIN`, по умолчанию `/opt/homebrew/opt/postgresql@17/bin`.

Остановка:

```sh
/opt/homebrew/opt/postgresql@17/bin/pg_ctl -D "$PWD/.runtime/postgres" stop
```

## Данные и восстановление

Контейнерный PostgreSQL описан в Compose-файлах, рабочие данные — в постоянном volume. Не удаляйте volume при обновлениях. Для резервной копии нужны дамп PostgreSQL и соответствующий ключ шифрования из каталога приложения; храните их приватно. Потеря ключа потребует повторного ввода параметров регистратора. Путь к `.runtime` не меняется при переносе исходников.
