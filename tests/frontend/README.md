# Проверка мобильного интерфейса

Сценарий открывает настоящий интерфейс в Chromium с профилем iPhone X. Проверяет поиск, редактирование доступов, сохранение названия камеры, приглашения, отмену добавления, защиту черновика и возврат из выбора камер. Дополнительно проверяются ширины 320, 390, 768 и 1440 px.

Стенд создаёт отдельную схему PostgreSQL с вымышленными данными и удаляет её при штатной остановке. Видео не подключается. Запускайте сценарий только на этом стенде: он изменяет тестовые записи.

Нужны зависимости бэкенда и Playwright с Chromium. Из корня репозитория, в первом терминале:

```sh
TEST_DATABASE_URL='<DSN тестового PostgreSQL>' PYTHONPATH=. \
  .runtime/venv/bin/python tests/frontend/fixture.py
```

Во втором терминале:

```sh
node tests/frontend/mobile.cjs
node tests/frontend/navigation.cjs
node tests/frontend/connection.cjs
node tests/frontend/actions.cjs
node tests/frontend/audio.cjs
node tests/frontend/audio-routing.cjs
node tests/frontend/audio-ui.cjs
node tests/frontend/archive-motion.cjs
node tests/frontend/reorder.cjs
node tests/frontend/buffering.cjs
node tests/frontend/player-startup.cjs
```

Если Playwright установлен вне проекта, задайте путь к модулю через PLAYWRIGHT_MODULE. Порт стенда задаётся UI_TEST_PORT, адрес в сценарии — UI_TEST_URL. Скриншоты сохраняются в `.runtime/screenshots/mobile-ux-check`; путь можно заменить через UI_SCREENSHOTS_DIR. Завершите стенд через Ctrl+C после проверки.

Для archive-motion.cjs нужен FFmpeg (`FFMPEG_BINARY`) и браузер с H.264 (`CHROME_EXECUTABLE`, если тестовая сборка Chromium не поддерживает кодек). Сценарий создаёт искусственный ролик во временной папке и удаляет его после проверки.

player-startup.cjs использует те же зависимости и синтетическое видео: первый кадр должен появиться без стартового запаса, а восстановительный буфер — включаться после опустошения потока. buffering.cjs проверяет границы и поведение адаптивного запаса без браузера. reorder.cjs проверяет захват всей камеры мышью, удержание на телефоне, немедленный захват за точки, предпросмотр сетки до отпускания, отмену, сохранение порядка и отсутствие новых подписок или замены видеоэлементов. `node tests/frontend/bench-reorder.cjs` измеряет перестановку 4/16/64 элементов DOM без камер и базы.

Профиль устройства проверяет размеры и touch-настройки, но не заменяет проверку Safari, клавиатуры и установки на физическом телефоне.

Второй сценарий проверяет открытие пользователей без промежуточного экрана, мобильное боковое меню (закрытие, фокус, смена ширины), подсветку всей строки на компьютере, сохранение порядка экранов, поздние ответы и повтор загрузки, выбор результатов поиска, закреплённое управление, создание и удаление группы, регистрацию по приглашению и доступ обычного пользователя.

Проверка connection.cjs подменяет только ответ статуса регистратора: имя и число каналов, отсутствие имени, ошибка и незаданное подключение. Проверяет, что обновление статуса сохраняет введённый черновик, а поля подключения остаются пустыми при открытии.

actions.cjs проверяет копирование ссылки обоими элементами диалога, отсутствие перехода, отзыв приглашения из списка и редактирование названия камеры на месте: отмену, ошибку, повтор и сохранение после перезагрузки.
