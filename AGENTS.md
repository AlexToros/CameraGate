## Product requirements

- Bootstrap the first administrator once; no default credentials. Two roles: admin and user.
- Users sign in, see only permitted cameras and save their own configurable video wall.
- Administrators can issue one-use invitations with preassigned first/last names, role and camera/group grants. Registration asks only for login and password.
- Administrators manage users, blocking, grants, camera groups and globally visible camera names.
- The built-in group «Все камеры» starts with all discovered channels, but its membership is editable. Exclusions affect only this group; other grants remain valid. Keep its name/deletion protected. Admins retain access to the full management catalog, while camera picking/preset additions default to the group's curated list.
- Device connection settings (ID, UserName, Password) are write-only in the API/UI. The admin connection endpoint exposes only allowlisted recorder name/channel count and catalog verification status. Read optional General.MachineName (including nested General.General) during the existing catalog operation; metadata failure must not break discovery. Reset metadata on credential replacement. Missing settings produce a useful viewer error.
- Blocking and permission changes must affect existing sessions and active streams, not only new requests.
- PostgreSQL in all environments; do not introduce SQLite. Keep Docker Compose and nginx configuration for later deployment, but simplify the local preview.
- Installable PWA is required. Finish core flows first, then verify responsive layouts and touch controls. Never cache authenticated API responses or video in the service worker.
- Show the install button only on mobile platforms (including iPad desktop UA), and hide it inside the installed app. A narrow desktop window is not a mobile platform.
- Invitation registration greets the assigned last/first name, explains the login, and asks for login/password/password confirmation. A mismatch must not submit or consume the invite.

- Password minimum is 6 characters, maximum 128, in both forms and backend. Existing users must survive routine restarts.
- Delete accepted and revoked invitations physically; purge expired/legacy inactive invitations in bulk. Keep only pending invitations in the UI.
- Keep the wall concise: no wall title, autosave progress/success labels or explanatory grid-fit text. Save silently and show errors when saving fails.
- Camera chooser lists cameras absent from the current wall first, then cameras already on it, preserving catalog order within each section. Mark existing wall cameras with a green dot labelled «На экране»; this denotes placement, not verified camera connectivity. Apply ordering under search and group filters too.

## Portal architecture

- Top-level boundaries: frontend/, backend/ (Python package), database/, infrastructure/, deployment/, scripts/dev/ and tests/backend/. Keep runtime state in root .runtime/; do not move databases or keys when reorganizing source. backend/paths.py resolves source paths independently of cwd.
- Launch: sh scripts/dev/start.sh or python -m backend. Native subprocesses use python -m backend.cameras.vesta with cwd set to the repository root; the optional gateway uses python -m backend.cameras.gateway. Keep PWA/public asset URLs unchanged when moving their files.

- `backend/server.py`: aiohttp HTTP/API and one multiplexed WebSocket per browser. Bind loopback locally. PUBLIC_ORIGIN/COOKIE_SECURE configure a future HTTPS entrypoint.
- `backend/store.py`, `database/schema.sql`: PostgreSQL 17, transactional bootstrap/invitations, server sessions, ACL snapshots and saved per-user grids. Passwords use salted PBKDF2; upstream credentials use Fernet with a separate runtime key.
- Initial SQL is idempotent; introduce versioned migrations before changing an already deployed schema.
- Built-in group exclusions use the existing settings row all_cameras_excluded_ids (JSON text); no schema change. The group snapshot joins that one setting in its existing bulk query and exposes effective membership. Preserve exclusions for temporarily missing channels; newly discovered IDs join automatically.
- Active users/rights/sessions are an in-memory bulk snapshot, refreshed atomically after mutations. This currently requires one portal process; replicas require shared invalidation and source coordination.
- `backend/cameras/relay.py`: one shared compressed source per camera; keep the effective built-in group connected continuously, reconcile every second from the in-memory snapshot. Cameras outside it remain viewable through existing grants on demand and expire 15 seconds after last demand. Never duplicate upstream sessions per viewer/tile. Default make_pool uses RelayPool; the old JPEG StreamPool remains diagnostic compatibility only.
- `backend/cameras/relay_worker.py`: one disposable native SDK hub process for all cameras, routed callbacks and lightweight per-camera sessions. At most two concurrent connects and one initialization subprocess. Credentials enter stdin; native stderr is suppressed, only safe channel/stage/error-type retries are logged. Worker and per-channel failures retry with bounded backoff; empty source sets stop the worker. SDK crashes must not kill the portal.
- `backend/cameras/connections.py`: bounded connection admission prioritizes recently viewed cameras and the event control session. Reserve every eighth admission for pending background warmup; wall changes reprioritize existing tickets without restarting working streams. Viewer demands merge across browsers, expire after two seconds and propagate through the optional gateway independently of the maintained source set.
- Live players show the first decoded frame immediately without accumulating a startup reserve. After actual playback starvation, refill an adaptive reserve (up to 1.5 seconds) before resuming the same decoder. Ordinary arrival jitter must not trigger repeated seeks; catch up only when more than three seconds behind. Pointer/touch reordering in `frontend/reorder.js` moves existing tiles without rebuilding players or changing subscriptions; only the grip captures touch scrolling.
- `backend/cameras/motion.py` handles VideoMotion and the observed appEventHumanDetectAlarm events. Keep AI events separate from the bulk VideoMotion mask; expire an unclosed human event after ten seconds. Safe event counters and media timing diagnostics are admin-only at `/api/admin/media/diagnostics`. Persist metadata-only motion logs in DATA_DIR/motion.log (256KiB, two backups); never log raw payloads, identifiers or credentials.
- `backend/cameras/mp4.py`: preserve compressed H.264/H.265 samples/FPS, one-time FFmpeg initialization with streamcopy, Python fMP4 live fragments; no continuous FFmpeg, JPEG encoding or server decoding. Current DVRIP cadence assumes no B-frame reordering; explicitly reject advertised reordering. Per-camera current+previous GOP cap 2MiB, keyframe wait cap 15s, total cache 64MiB, output batches 4MiB. Preserve unsent GOP tails across keyframes; new viewers start at the latest keyframe, lagging existing viewers jump there without another initialization. Reinitialize MediaSource only for a new source generation; repeated init on ordinary GOP gaps causes brief black flashes. Set SourceBuffer timestampOffset only once per player. Ignore stale worker source tokens and generations.
- `backend/cameras/vesta.py` owns only the native transport/decoder. Credentials enter worker stdin, never command-line arguments. Native media workers skip redundant catalog queries; catalog discovery is separate.
- `backend/cameras/gateway.py` and `backend/cameras/gateway_client.py`: optional token-authenticated media worker. Browser access to the gateway is forbidden. Linux x86_64 can run native workers with CAMERA_SDK_PATH pointing to its separate ELF library and FFMPEG_BINARY=/usr/bin/ffmpeg; macOS keeps Rosetta and dylib. Proprietary binaries stay outside git and are mounted read-only.
- `frontend/app.js`, `frontend/player.js`, `frontend/style.css`: vanilla UI; wall presets 1/4/6/9/16, custom widths and reordering. Video uses MediaSource/ManagedMediaSource with muted inline autoplay; native browser codec support is required, particularly for H.265. Do not hide video before first playback: WebKit evaluates visibility for autoplay. Set defaultMuted/muted/playsInline and disable native controls; handle NotAllowedError with a single shared gesture, never individual Play overlays. Keep only one pending play promise per player. Last-frame snapshots stay only in client canvas memory (at most one copy/second); retain them during recovery with an amber indicator and explicit stale label, hide on resumed playback. Camera switching/revocation removes the old tile and its snapshot. Expansion uses the existing picture/video in fullscreen, WebKit native video fallback or viewport fallback; never open a modal or create another decoder. Skip tile rebuilds on height-only resizes and while a camera is fullscreen. Tile picture height follows video dimensions; ResizeObserver measures intrinsic tiles for dense CSS row spans. Legacy saved height stays compatible without stretching. Keep captions minimal. Mobile may reduce visible columns without changing saved layout. CSP media-src allows same-origin/blob; SW never caches media.
- Invitation links must be actual clickable anchors. Handle hash navigation in an already open app; ignore late responses from a previous route so they cannot replace the registration form.
- Root startup checks /api/me and /api/state first: a valid cookie opens live view without a login flash or bootstrap round trip. Only a 401 falls back to bootstrap/login. Explicit invitation routes retain priority even with a valid session cookie.
- `frontend/admin.js` owns administration. Hash routes use #/admin/section/id; management opens Users directly; mobile navigation uses a hamburger drawer, desktop uses a permanent sidebar. Users/groups open editors through whole-row buttons. Invitations have a direct revoke action in the list; creating one shows a dialog whose URL and small copy button both copy the link. Camera names edit inline with Enter/save and Escape/cancel; keep the draft guard and an error beside the input. Editors use one page scroll with sticky back/save; access picking has search and selected counts, with browser Back returning to the draft. Hide ACL controls for admin roles. Keep unsaved drafts in memory only, confirm before leaving; admin routes/history.state must not contain credentials or invitation tokens (the existing registration links use their required #/invite/token route). Ignore responses for detached views and retain navigation during loading/errors. Camera renaming submits one existing bulk API call for the selected camera. Disconnect tile observers on route/logout; clear fullscreen layout when leaving the session.
- `frontend/audio.js`: one opt-in audible tile per page, G.711 A-law/8kHz decoded by WebAudio. Keep video muted for autoplay. WebSocket audio_camera_id must belong to the same authorized video selection; revoke/block/logout/hidden tab must stop sound. Audio stays compressed server-side, comes from the existing shared source, has a bounded one-second/16kB cache per channel and only reaches viewers who select it. Kind4 carries codec14/rate2/float64 source time + A-law. Flush audio on camera/generation changes and video stalls; bounded scheduling follows the selected video timeline. Audio errors/backpressure must not restart video.
- `backend/cameras/motion.py`: one shared control connection in the native hub subscribes to recorder motion events and reconciles one bulk WorkState snapshot. Never enable or reconfigure detection automatically. Motion failure must not stop live media; expire stale snapshots and filter notifications by each viewer's current subscriptions and permissions. The walking-person marker denotes recorder motion, not person recognition.
- `backend/archive.py`, `backend/cameras/recorder.py`/`recorder_worker.py`: admin-only recorder archive, bounded date/camera search pages and private expiring recording references. Playback must use ByName to preserve channel identity; use recorder keyframe timestamps for its clock. Streamcopy fMP4 without video decoding or recording files on the portal. Native archive processes close the recorder session on SIGTERM; serialize replacement per administrator and allow at most two active viewers. Recheck role/session/config while streaming. Optional private gateway supports both archive and motion.
- `frontend/archive.js`: separate bounded MSE player in the admin Archive section. Pause closes the upstream archive source; resume/seek opens it at the requested recording time. Release media on navigation/logout/hidden tab. Never apply the live player's catch-up seeks to recorded video; no archive API/media caching in the PWA.
- Manifest/icons/service worker implement PWA. Only public app-shell assets may enter CacheStorage. Phone installation requires trusted HTTPS; desktop localhost works for local preview.
- `infrastructure/compose.yaml` keeps the local optional gateway setup. `deployment/compose.production.yaml` runs native Linux transport, PostgreSQL and nginx with memory/log limits; only nginx publishes 80/443. Encrypted connection data requires the matching /data/secret.key when migrating the DB. Do not expose initial bootstrap publicly before restoring the existing user database.
- Production TLS: Certbot webroot /var/www/letsencrypt, HTTP challenge in infrastructure/nginx/acme.conf, infrastructure/nginx/production.conf after issuance. deployment/scripts/enable-https.sh installs the deploy hook and enables certbot.timer; deployment/scripts/renew-certificate.sh validates and reloads nginx after renewal.
- TRUST_PROXY=1 is production-only: app has no published port, nginx overwrites X-Real-IP, and login throttles use that validated client IP. Never enable it with direct untrusted access to app. The local optional gateway compose leaves it off.
- PUBLIC_ORIGIN is the primary host; ADDITIONAL_PUBLIC_ORIGINS is an explicit comma-separated allowlist. Select CSP/WebSocket origin by the configured request Host, and require Origin to match that host, even when another host is also allowed. Certbot certificate name bogdanova34-portal covers both domains; HTTPS readiness marker is certificate-specific.

## Existing video transport

- Original prototype: Python HTTP server, single shared selected camera, MJPEG browser player.
- VestaCloud uses XMEye/Xiongmai P2P and DVRIP. Only the low-level `vv_nat_*` functions are used; the high-level vendor login crashed.
- macOS x86_64 vendor library lives in ignored `.runtime/libnetsdk.dylib`. Rosetta is required on Apple Silicon for the transport process; FFmpeg is native.
- Never expose serial number, device login/password, password-equivalent hashes or raw SDK output. Native stdout/stderr are silenced before loading the library.
- DVRIP media must be routed by message id, assembled across packets and decoded only from a complete keyframe. Reject packets from another DVRIP session.
- SDK send length includes a 12-byte transport envelope. Start-monitor does not necessarily return an acknowledgement.
- Each stream must isolate stale frames by generation. The browser must wait for the actual new image before revealing it.
- Do not confuse SDK connection caching with web caching. Disabling the old SDK cache was a compatibility workaround, not a proven speed optimization.
- Dynamic P2P discovery remains the default. An operator may override it with `P2P_SERVER` or ignored `.runtime/p2p-server` when a discovered node cannot reach the recorder. Public node addresses can change; never bake one into the source.

## Validation

- `.runtime/venv/bin/python -m unittest discover -s tests -t . -v`; PostgreSQL suites require TEST_DATABASE_URL and use disposable schemas.
- Verify authorization, concurrent bootstrap/invite consumption, active stream revocation/blocking and layout persistence against real PostgreSQL.
- Exercise Chromium desktop/mobile and real streams separately. Artificial image fixtures prove UI/ACL behavior, not real camera availability.
- For wall changes, verify actual frame proportions (including 4:3 and widescreen), non-overlapping tiles, search, shared preview, width/order, add/remove and persistence. Check 320/390/768/1440 widths, touch controls and delayed admin responses without touching real accounts.
- Keep CSP enabled during product validation. Playwright waitForFunction uses eval and conflicts with CSP; use locators/polling instead of weakening product policy.
- `node --check frontend/app.js`, `node --check frontend/sw.js`, `docker compose -f infrastructure/compose.yaml config --quiet`.
